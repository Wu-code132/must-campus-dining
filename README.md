# 菜品数据样例说明

本目录包含菜品表结构与初始化数据，以及一个用于接口联调的 JSON 示例。数据均为课程演示用合成样例，不代表食堂实时菜单、真实价格或官方过敏原信息。

## 文件说明

| 文件 | 用途 | 内容 |
|---|---|---|
| `init_dish.sql.txt` | 创建 `Dish` 表并插入初始化样例 | 20 条菜品记录，覆盖食堂、价格、辣度、口味、售卖状态、数据来源和过敏原 |
| `dish_mock.txt` | 模拟接口返回的 JSON 文本 | 一个成功响应示例，目前 `data` 数组只有 2 条记录 |

## 数据字段

SQL 表 `Dish` 包含以下字段：

| 字段 | 含义 |
|---|---|
| `dish_id` | 菜品编号，主键 |
| `dish_name` | 菜名 |
| `canteen` | 食堂或档口名称 |
| `price` | 价格 |
| `spiciness` | 辣度 |
| `flavor` | 口味描述 |
| `status` | 售卖状态：`ON_SALE`（在售）或 `OFF_SALE`（下架） |
| `data_source` | 信息来源：`OFFICIAL`（官方）或 `USER_REPORTED`（用户上报） |
| `allergen_info` | 过敏原文本，多个值以逗号分隔 |

JSON 示例使用驼峰命名：`dishId`、`dishName`、`dataSource`、`allergens`。接入接口时需按后端约定统一字段命名和过敏原的数据格式。

## 使用说明

1. 先确认目标数据库和表名，再执行 `init_dish.sql.txt`。
2. 该脚本会创建 `Dish` 表并插入 20 条记录；重复执行会因表或主键已存在而报错。需要重置时，请先备份并按项目约定清理演示数据。
3. `dish_mock.txt` 是接口响应格式示例，不是 SQL 初始化数据，也不包含完整的 20 条菜品记录。

如果使用 SQLite 命令行，可在数据库文件所在位置执行：

```powershell
sqlite3 campus.db ".read init_dish.sql.txt"
```

请将 `campus.db` 替换为实际数据库文件路径。若项目数据库已有同名 `Dish` 表，不要直接重复导入。

## 当前样例差异

`dish_mock.txt` 中的 `D001` 和 `D002` 已按 `init_dish.sql.txt` 对齐菜名、食堂、价格、辣度、口味、状态、来源和过敏原。JSON 目前仅保留 2 条接口响应示例，并非 SQL 中 20 条记录的完整导出。

此外，SQL 使用 `allergen_info` 字符串字段，JSON 使用 `allergens` 数组；两者格式不同，需由接口契约明确转换规则。

## 注意事项

- 所有菜品、价格、状态和过敏原均为合成演示数据，使用前应核实。
- 不要将用户上报信息标记为官方信息；展示时应保留 `data_source` 来源提示。
- 推荐或筛选时应遵守售卖状态，并将信息缺失情况明确提示。
